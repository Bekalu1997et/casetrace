# Refactor 01 — Specification gap matrix

Baseline and executed evidence: [current-state audit](01-current-state-audit.md).
Authority and conflict resolutions: [compatibility](04-contract-compatibility.md).
Paths are exact repository-relative implementation references; named symbols
identify the relevant section. Status assesses the stated requirement, not the
entire containing module.

Status vocabulary: **Fully implemented**, **Partially implemented**, **Missing**,
**Implemented differently by approved design**, **Obsolete or superseded**,
**Requires clarification**. “Approved design” refers to the explicit Phase 2/3/4
decision notes, not retroactive approval of implementation convenience.

Severity: High = evidence/investigation integrity or a principal product capability;
Medium = architecture, inspectability or significant UX gap; Low = polish or
historical documentation debt; None = satisfied or intentionally superseded.
Milestones R02–R10 are defined in the [backlog](05-refactoring-backlog.md).
